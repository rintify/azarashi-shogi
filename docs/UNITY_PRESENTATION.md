# Unity版の表現の移植

元版の表現の定義は `src/components`、`src/styles.css`、`src/scene`、`src/presentation` にある。Unity側で独自のデザインを作って置き換えない。

## データの所有者

- `NativeMatch`: 対局状態、操作意図、安全性。Rustが返した合法手を使う。
- `NativeHud`: UI状態。Stock / Dialogs / Flow / Catalog / Status / Modality / Promotion / Feedbackに分割した部分クラスは同じ所有者のビュー。
- `NativeViewTree`: 継続するUI要素の同一性と退場時の保持。再描画でフォーカスやポインターキャプチャーを破棄しない。
- `NativeUi`: UIの登場・退場・値の切り替え・押下・ホバー。元のCSSの曲線を使う。
- `NativeMotion`: 元のmotion / movement / captureTransfersの秒単位移植。駒、捕食、粒子、持ち駒は同じ時計を参照する。
- `NativeGuides`: 元のguideStyleの優先順位、色、透過率。描画層で安全判定を追加しない。
- `NativeBoard`: エクスポートされたモデル、連続したペンギンの姿、盤上ガイドの保持・補間。
- `NativeEffects`: 元のTravelEffects / SnowImpact / ActionEffectsの粒子プール、形状、経路、寿命。
- `SceneRenderer`: 右手座標からUnityへの変換、描画、元の物理照明式。UIやルールは持たない。

## 元の素材の取り込み

`npm run unity:build` は、TSXモデルと途中のペンギンの姿、粒子のジオメトリー、AnimalIconとLucideのSVG、CSSの多層シャドウの数値、ルール本文を生成する。影を厚い下枠に置き換えたり、記号を別の図形で描き直したりしない。SVGから生成するUI画像は圧縮・ミップマップを無効にして取り込む。

CSSの影は`Presentation.json`のレイヤー（座標、blur、spread、色、透明度）を読み、部品の外側の枠を基準にした兄弟要素として描く。UI ToolkitのネイティブGaussian blurを使用し、CSSのbox/text-shadowのblurの半分をsigmaへ渡す。以前のSVGマスクのフィルター領域切れと9スライスによるぼかしの変形を避ける。複数の文字影も同じレイヤー契約を使う。

モーダルの背景は、ネイティブの3DカメラのRenderTextureとHUDを同じUIレイヤーへ合成し、そのレイヤーへ元CSSの7pxぼかしを適用する。ダイアログ本文はその外に描く。Reactを実行時に重ねる構成ではない。Unity 6000.5の`IStyle.filter`を使用し、存在しない`backdropFilter`には依存しない。

場面の環境照明は元のThree.jsが生成したPMREMをlinear RGBA half floatで保持する。UnityのStandardシェーダーへの単純置換ではなく、元のGGX、clearcoat、多重散乱、CubeUVサンプリングとACESを移植している。色をsRGBへ二度変換しない。図鑑には元の図鑑専用の照明と床を使う。

素材契約の色は既に線形値なので、ShaderLabの `_Color` / `_Emission` は `Vector` として宣言する。`Color` 宣言では、`SetVector` で渡してもsRGBから線形への変換が入る。2026-10-20の実WebGL照合で、この二重入力変換による海と駒の暗転を確認し、宣言を修正した。手動の出力ガンマ変換は追加していない。Editor検証はこの型の契約もチェックする。照明・影の細部の一致は別途照合が必要。

環境光の強度はThree r180の `WebGLRenderer` と同じ条件で選ぶ。明示的な材質の `envMap` がないStandard/Physical材質には、材質の `envMapIntensity` ではなく場面の `environmentIntensity` が適用される。`SceneEncoder` はこの区別を `useSceneEnvironment` で出力し、元場面から採取した強度をUnityで使用する。盤面用・動物用モデルを別々に採取しても、この場面の条件を失わない。図鑑は図鑑専用の照明を使用する。

環境照明と捕食音の再生成は開発サーバーの `?unity-environment` 画面から行う。環境は元のIceWorldを実際のWebGLで描画して保存し、音は元のscheduleBiteをOfflineAudioContextでレンダリングする。出力はそれぞれ `Native/Lighting/Environment.bytes`、`Native/Audio/Bite.bytes`。`PresentationSources.json` は採取元のSHA-256を保持し、変更後の古い素材の使用をビルド前に拒否する。

## 検証

`unity-presentation-fixtures.ts` が元のTypeScript関数から動作とガイドの照合データを生成する。Unity Editorの `PresentationValidation` が移動・変身・王の伸縮・飛行と持ち駒の到着時刻、全32,768通りのガイド状態を照合する。対局の15手の棋譜もRust経由で再生して確認する。

カメラの左右の回転経路は、元の `sampleCameraOrbit` が生成した246サンプルで比較する。Unity座標を元の右手座標へ戻してから補間し、最後にZを反転する。HUD領域が未確定の初回フレームではカメラを更新せず、ゼロ幅によるNaNと、その後の盤面消失を防ぐ。起動順の回帰検証もEditorで実行する。

数値の照合は見た目全体の一致を保証しない。シェーダー、シャドウ、UI Toolkitの文字組み、画面サイズ、hoverと退場中の入力について、実際のUnity Webビルドでも確認する。

- 起動直後の未確定HUD領域からカメラがNaNになる不具合を実画面で確認し、修正後の盤面描画を確認。
- 元素材の線形色を二重変換しない材質宣言と、元Threeの場面環境光の適用条件を修正。海・盤面・王を同じ初期局面で比較。
- ヘッダーの縦方向の中央揃え、横画面で幅840px以上の盤面領域、相手の持ち駒の横並び・右寄せを元CSSに対応。

- ScrollViewの内部contentContainerもNativeViewTreeの管理下へ登録。レイアウト更新で本文が重複する不具合を修正し、要素の同一性・重複防止・退場時の入力停止をEditor検証に追加。

## UIの追加照合（2026-10-20、継続中）

追加ビルドは`2026-10-19T18:23:34.591Z`（日本時間03:23）に完了。React本番ビルド・型チェック、36ファイル241件のテスト、従来のUnity数値照合とRustの15手検証を通過。元のUIから抽出した成り候補の提示・確認条件も469行き先（自分の王の捕食確認17ケースを含む）で照合した。

- アイコンは枠線を除いた領域の中央へ配置。SVGの切り替えは配置用要素を動かさず、中の画像だけを元の180/220msの切り替えで描く。
- ボタン、持ち駒、選択肢、ダイアログと文字の多層影を、元CSSのレイヤーからネイティブ描画へ変更。SVGマスクの領域切れと9スライスでぼかしが変形する問題を除いた。
- 7pxの背景ぼかしをWebGL実画面で確認。設定・ルール・リプレイは本文を通常のフローで配置し、カード全体をスクロールする。文字を推定行数の固定高さへ押し込まない。
- 設定モード切り替えで、保持した要素を宣言順へ並べ直す。説明が開始・取消ボタンの後へ回る不具合を実画面で確認して修正し、要素の同一性を保つ順序の回帰検証を追加した。
- 図鑑は元CSSの縦・横配置へ対応。動物を回す代わりに、元のOrbitControlsと同じ方向・速度でカメラを周回させ、縦ドラッグ・拡大縮小も扱う。
- 元の手番表示の記号・小さい文字・文言、座標の上下、リプレイの塗りつぶした再生記号とサイズを復元。紫色のガイドは元と同じくシャチの安全な回転候補がある場合に限る。
- 自分の王を捕食する手の確認を復元。この単一候補では、元と同じく決定前に移動しない。React側の元の条件を副作用のない関数へ抽出して両実装を照合する。ルール・AIの権限はRustのまま。
- マークの再登場、退場済みUIの保持・解放、モーダルのTab移動とEscape、スライダーのフォーカス表示を調整した。

追加のブラウザー検証にはUnity `http://127.0.0.1:4188/` とReact `http://127.0.0.1:5188/` を使用し、保存済み対局のあるオリジンとは分離している。縦375×812と横844×390で図鑑、縦画面で設定の折り返し・モード切り替え・背景ぼかしを確認した。自捕食・勝敗画面は元版の実寸を取得しており、Unity側での同じ操作の照合を続ける。

残っている確認・差分:

## 影と保持UIの追加修正（2026-10-20 03:53）

通常のUnity Webビルドを`2026-10-19T18:53:29.351Z`に完了。36ファイル241件、React本番ビルド・型チェックも通過した。

- Unity組み込みの影を、元Three r180のRGBA深度とPCFSoftサンプリングへ変更。元の光源から影用カメラの投影・ビュー・UV行列、解像度、receiver bias / normal bias / intensityを出力する。Unityのcaster biasで代用しない。盤面2048、図鑑1024の54点で元の投影を照合し、図鑑の接地影を実WebGLでも観察した。最終的な全局面の出力照合は継続する。
- 図鑑の環境と床を`CatalogEnvironment`へ切り出し、元Canvasとエクスポートで共有。照明・床材質の重複したUnity定数を除いた。
- ローカルPvPのカメラ交代完了時に、保持したボタンの無効状態を更新する。上の相手欄と下の持ち駒欄は、所有者によらずそれぞれ同じUI要素を保持する。交代後に持ち駒が開けない不具合を実操作で確認し、修正後の開閉・配置を確認した。
- 自分の王を捕食する手の警告・取消・再選択・決定と、勝利画面の375×812 / 844×390 / 1280×800の表示を確認。結果画面の文字影を追加しながら子要素を列挙して起きる例外を修正し、修正後の再表示で新しい例外がないことを確認した。
- 短い設定画面が再描画で最大高さへ戻る問題を修正。スクロール領域の最小高さに依存せず、通常フローの子要素を計測し続ける。375×812のローカルPvP設定の自然な高さと中央配置を実画面で確認した。
- 捕食後の持ち駒の到着リング、加算の文字影・位置・900msの曲線を元CSSへ対応。勝敗の光線は円錐グラデーションと放射状マスク、紙片は元のease-inを使う。これらの途中フレームの照合は継続する。

元版では両王捕食の確認と引き分けを実操作で再現した。Unity側での引き分け・敗北、全回転候補、全エフェクトの実画面照合はまだ完了扱いにしていない。
