# Unity版の表現の移植

元版の表現の定義は `src/components`、`src/styles.css`、`src/scene`、`src/presentation` にある。Unity側で独自のデザインを作って置き換えない。

## データの所有者

- `NativeMatch`: 対局状態、操作意図、安全性。Rustが返した合法手を使う。
- `NativeHud`: UI状態。Stock / Dialogs / Flow / Catalog / Status / Modality / Promotion / Feedbackに分割した部分クラスは同じ所有者のビュー。
- `NativeViewTree`: 継続するUI要素の同一性と退場時の保持。再描画でフォーカスやポインターキャプチャーを破棄しない。
- `NativeUi`: UIの登場・退場・値の切り替え・押下・ホバー。元のCSSの曲線を使う。
- `NativeMotion`: 元のmotion / movement / captureTransfersの秒単位移植。駒、捕食、粒子、持ち駒は同じ時計を参照する。
- `NativeGuides`: 元のguideStyleの優先順位、色、透過率。描画層で安全判定を追加しない。
- `NativeBoard`: エクスポートされたモデル、連続したペンギンの姿、盤上ガイドの保持・補間。
- `NativeEffects`: 元のTravelEffects / SnowImpact / ActionEffectsの粒子プール、形状、経路、寿命。
- `SceneRenderer`: 右手座標からUnityへの変換、描画、元の物理照明式。UIやルールは持たない。

## 元の素材の取り込み

`npm run unity:build` は、TSXモデルと途中のペンギンの姿、粒子のジオメトリー、AnimalIconとLucideのSVG、CSSの多層シャドウの数値、ルール本文を生成する。影を厚い下枠に置き換えたり、記号を別の図形で描き直したりしない。SVGから生成するUI画像は圧縮・ミップマップを無効にして取り込む。

CSSの影は`Presentation.json`のレイヤー（座標、blur、spread、色、透明度）を読み、部品の外側の枠を基準にした兄弟要素として描く。UI ToolkitのネイティブGaussian blurを使用し、CSSのbox/text-shadowのblurの半分をsigmaへ渡す。以前のSVGマスクのフィルター領域切れと9スライスによるぼかしの変形を避ける。複数の文字影も同じレイヤー契約を使う。

モーダルの背景は、ネイティブの3DカメラのRenderTextureとHUDを同じUIレイヤーへ合成し、そのレイヤーへ元CSSの7pxぼかしを適用する。ダイアログ本文はその外に描く。Reactを実行時に重ねる構成ではない。Unity 6000.5の`IStyle.filter`を使用し、存在しない`backdropFilter`には依存しない。

場面の環境照明は元のThree.jsが生成したPMREMをlinear RGBA half floatで保持する。UnityのStandardシェーダーへの単純置換ではなく、元のGGX、clearcoat、多重散乱、CubeUVサンプリングとACESを移植している。色をsRGBへ二度変換しない。図鑑には元の図鑑専用の照明と床を使う。

素材契約の色は既に線形値なので、ShaderLabの `_Color` / `_Emission` は `Vector` として宣言する。`Color` 宣言では、`SetVector` で渡してもsRGBから線形への変換が入る。2026-10-20の実WebGL照合で、この二重入力変換による海と駒の暗転を確認し、宣言を修正した。手動の出力ガンマ変換は追加していない。Editor検証はこの型の契約もチェックする。照明・影の細部の一致は別途照合が必要。

環境光の強度はThree r180の `WebGLRenderer` と同じ条件で選ぶ。明示的な材質の `envMap` がないStandard/Physical材質には、材質の `envMapIntensity` ではなく場面の `environmentIntensity` が適用される。`SceneEncoder` はこの区別を `useSceneEnvironment` で出力し、元場面から採取した強度をUnityで使用する。盤面用・動物用モデルを別々に採取しても、この場面の条件を失わない。図鑑は図鑑専用の照明を使用する。

環境照明と音の再生成は開発サーバーの `?unity-environment` 画面から行う。環境は元のIceWorldを実際のWebGLで描画して保存し、音は元のscheduleBiteとscheduleToneをOfflineAudioContextでレンダリングする。出力は `Native/Lighting/Environment.bytes`、`Native/Audio/Bite.bytes`、`Native/Audio/Tones.bytes`。`PresentationSources.json` は採取元のSHA-256を保持し、変更後の古い素材の使用をビルド前に拒否する。

## 検証

`unity-presentation-fixtures.ts` が元のTypeScript関数から動作とガイドの照合データを生成する。Unity Editorの `PresentationValidation` が移動・変身・王の伸縮・飛行と持ち駒の到着時刻、全32,768通りのガイド状態を照合する。対局の15手の棋譜もRust経由で再生して確認する。

数値の照合は見た目全体の一致を保証しない。シェーダー、シャドウ、UI Toolkitの文字組み、画面サイズ、hoverと退場中の入力について、実際のUnity Webビルドでも確認する。

## WebGLのUI更新停止への対処（2026-10-20 04:26）

設定モードの切り替えでWebGLのOOMとメモリー範囲外アクセスを再現した。外部シンボル付きビルドで、UI Toolkitの`GpuUpdaterStaged`からGPUバッファを更新する経路と特定。生成されたC++でも、領域の統合前の件数からコピー先を確保する不具合を確認した。Unityが確認した[UUM-151098](https://issuetracker.unity.com/issues/24430)および[元の報告とUnity側の回答](https://discussions.unity.com/t/webgl-6000-5-2f1-ui-toolkit-staged-updater-under-sizes-its-staging-buffer-copybufferranges-reads-out-of-bounds-on-large-single-frame-restyles/1731377)と一致する。6000.5への修正提供はない。

`scripts/unity-editor-copy.mjs`と`Editor/UirStagingPatch.cs`で、6000.5.8f1のWebGL用モジュールのプロジェクト専用コピーを修正する。統合を確保前に実行し、その後の各範囲のインデックス位置の丸めに最大2個ずつを追加して確保する。インストール済みUnityのDLLは変更せず、元とコピーのSHA-256も検査する。専用コピーは`.openai/tooling/unity-build-editor/`にキャッシュし、元のDLLと修正コードが変わった場合は再生成する。Unity付属のCecilを使い、対象バージョン・ILの形が違う場合は書き換えない。

実際の`DataSet.ConsolidateRanges`を使った5ケースの回帰検証を追加。8192・65536・262144付近の範囲拡大と、疎なインデックス範囲の端数調整を含む。補正が実際のIL2CPP生成コードへ入ったことも確認した。補正後の通常ビルドは`2026-10-19T19:26:11.079Z`に完成。設定のローカルPvP・対AI・観戦の切り替えと、スライダーのドラッグ・Home・Endを実画面で通過している。
